## The model — single file per attribute

Marten stores files through `:file` and `:image` field types. **One field = one file**. There is no `has_one_attached` / `has_many_attached`. If you need multi-attach or variants, hand-roll an `Attachment` table (see section 10).

`:image` accepts the same options as `:file` but also validates that the uploaded content is an image. Requires the `crystal-vips` shard.

The DB column stores only the storage-relative path (a `VARCHAR`). The field object wraps that path and delegates I/O to the configured storage backend.

---

## Defining a file field

```crystal
class Document < Marten::Model
  field :id, :big_int, primary_key: true, auto: true

  # Default: stored at the storage root
  field :attachment, :file, blank: false, null: false

  # Fixed sub-path
  field :thumbnail, :image, blank: true, null: true, upload_to: "thumbnails"

  # Dynamic path via proc
  field :report, :file, blank: true, null: true,
    upload_to: ->(name : String) { File.join("reports", Time.utc.year.to_s, name) }
end
```

`upload_to` accepts a `String` prefix or a `Proc(String, String)`. Collision-avoidance (`_a1b2c3d4` suffix) is applied automatically by the storage's `#save` method.

To use a non-default storage for one field:

```crystal
private_store = Marten::Core::Storage::FileSystem.new(root: "/mnt/private", base_url: "/private/")
field :contract, :file, storage: private_store
```

---

## Reading a file

```crystal
doc = Document.first!
f = doc.attachment            # => Marten::DB::Field::File::File

f.attached?                   # true if a path is stored
f.committed?                  # true if the file exists in storage (vs. just assigned in memory)
f.name                        # => "reports/2025/summary_a1b2c3d4.pdf"
f.size                        # => Int64 (delegated to storage)
f.url                         # => "/media/reports/2025/summary_a1b2c3d4.pdf"
f.open                        # => IO  (opens the file from storage)
```

`.url` returns the storage-relative URL, e.g. `/media/foo.txt`. The prefix comes from `media_files.url` (default `/media/`).

---

## Writing / updating

Assign a `::File` (Crystal stdlib) or a `Marten::HTTP::UploadedFile` (from a multipart request), then save:

```crystal
# From disk
File.open("report.pdf") do |io|
  doc.report = io
  doc.save!
end

# From a multipart upload — typical handler pattern
class UploadDocHandler < Marten::Handlers::Schema
  schema UploadDocSchema   # schema has field :attachment, :file
  template_name "upload.html"
  success_url "/"

  def process_valid_schema
    uploaded = schema.validated_data["attachment"].as(Marten::HTTP::UploadedFile)
    Document.create!(attachment: uploaded)
    super
  end
end
```

`Marten::HTTP::UploadedFile` is what arrives from a multipart form (temp-file backed IO, exposes `#filename`, `#size`, `#io`, `#content_type`). Assign it directly to a `:file` field.

## Deleting

```crystal
doc = Document.first!
doc.attachment.delete          # removes from storage, clears the DB path (record NOT auto-saved)
doc.attachment.delete(save: true)  # same + calls record.save
```

## Storage backends

All storages subclass `Marten::Core::Storage::Base`. The abstract interface:

| Method | Signature | Notes |
|---|---|---|
| `write` | `(filepath, content : IO) : Nil` | Destructive overwrite |
| `save` | `(filepath, content : IO) : String` | Calls `write`; returns unique path |
| `delete` | `(filepath) : Nil` | |
| `open` | `(filepath) : IO` | Raises `FileNotFound` if missing |
| `exists?` | `(filepath) : Bool` | |
| `size` | `(filepath) : Int64` | |
| `url` | `(filepath) : String` | |

`#save` is concrete on `Base`; it appends `_<8-hex-chars>` to the stem until a free path is found, then delegates to `#write`.

**Built-in:** `Marten::Core::Storage::FileSystem.new(root: "media", base_url: "/media/")` — local disk.

**Community:** [`marten-s3`](https://github.com/martenframework/marten-s3) for AWS S3.

## Configuring storage

In `config/settings/base.cr` (or environment-specific):

```crystal
Marten.configure do |config|
  # Media files (uploaded user content)
  config.media_files.root    = "media"         # filesystem path
  config.media_files.url     = "/media/"       # URL prefix used by .url
  config.media_files.storage = Marten::Core::Storage::FileSystem.new(
    root: "media", base_url: "/media/"
  )

  # Static assets
  config.assets.root    = "assets"
  config.assets.url     = "/assets/"
  config.assets.storage = Marten::Core::Storage::FileSystem.new(
    root: "assets", base_url: "/assets/"
  )
end
```

Dev route for media (auto-generated by `marten new`):

```crystal
if Marten.env.development?
  path "#{Marten.settings.media_files.url}<path:path>",
    Marten::Handlers::Defaults::Development::ServeMediaFile, name: "media_file"
end
```

Do not use `ServeMediaFile` in production — point a web server or CDN at `media_files.root` instead.

## Custom storage backend

Subclass `Base` and implement the six abstract methods plus `#write`. Constructor is free-form.

```crystal
class S3Storage < Marten::Core::Storage::Base
  def initialize(@bucket : String, @prefix : String, @base_url : String)
    @client = S3::Client.new   # hypothetical shard
  end

  def write(filepath : String, content : IO) : Nil
    @client.put("#{@prefix}/#{filepath}", content)
  end

  def delete(filepath : String) : Nil
    @client.delete("#{@prefix}/#{filepath}")
  end

  def open(filepath : String) : IO
    @client.get("#{@prefix}/#{filepath}")
  rescue
    raise Marten::Core::Storage::Errors::FileNotFound.new(filepath)
  end

  def exists?(filepath : String) : Bool
    @client.exists?("#{@prefix}/#{filepath}")
  end

  def size(filepath : String) : Int64
    @client.size("#{@prefix}/#{filepath}")
  end

  def url(filepath : String) : String
    File.join(@base_url, filepath)
  end
end
```

Assign it:

```crystal
config.media_files.storage = S3Storage.new(
  bucket: "my-bucket", prefix: "uploads", base_url: "https://cdn.example.com"
)
```

## Static assets

Source files live in `src/assets/` (per-app) or directories listed in `config.assets.dirs`.

In templates:

```html
<link rel="stylesheet" href="{% asset 'app/app.css' %}">
<script src="{% asset 'app/app.js' %}"></script>
```

In Crystal:

```crystal
Marten.assets.url("app/app.css")  # => "/assets/app/app.css"
```

**Dev:** `ServeAsset` handler finds assets from source dirs without needing `collectassets`.

**Production:** run `bin/marten collectassets` (add `--fingerprint` for cache-busting). Serve the `assets.root` folder via Nginx, or point `assets.storage` at a CDN bucket. `Marten::Middleware::AssetServing` is an in-process fallback when a web server can't be configured.

Fingerprinting + manifests:

```crystal
config.assets.manifests = ["src/assets/build/manifest.json"]
```

## Active-Storage-like patterns (blob/attachment with variants)

Marten does not ship `has_one_attached` / `has_many_attached`. The pattern is: a polymorphic `Attachment` model with a `:file` field plus optional self-FK for variants.

**Model shape** (see `marten-writebook/src/storage/attachment.cr`):

```crystal
class Attachment < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :record, :polymorphic, to: [Book, Picture, Markdown], related: :attachments
  field :name, :string, max_size: 64       # attribute name on host, e.g. "cover"
  field :file, :file, blank: false, null: false, upload_to: "attachments"
  field :variant_of, :many_to_one, to: Attachment, related: :variants,
    blank: true, null: true, on_delete: :cascade
  field :variation_kind, :string, max_size: 64, blank: true, null: true
  field :content_type, :string, max_size: 128, blank: true, null: true
  field :byte_size, :big_int, blank: true, null: true

  with_timestamp_fields
  db_index :attachment_record_idx, field_names: [:record_type, :record_id, :name]
end
```

**Helper module** (see `marten-writebook/src/storage/attachment_helpers.cr`):

```crystal
# Attach original + pre-compute variants at upload time
AttachmentHelpers.attach(
  record: picture,
  name: "image",
  uploaded_file: uploaded,
  variants: {"large" => {max_dimension: 1500}},
)

# Lookups
cover    = AttachmentHelpers.find_one(record: book, name: "cover")
uploads  = AttachmentHelpers.find_many(record: markdown, name: "uploads")
resized  = AttachmentHelpers.variant_of(cover, kind: "large")
```

Key points:
- Variants are **pre-computed on upload** (via `crystal-vips` resize), not on demand.
- Each variant is its own `Attachment` row pointing back to the original via `variant_of_id`.
- Multiple rows with the same `(record_type, record_id, name)` = `has_many_attached`-style collection.
- The polymorphic `:record` field stores `record_type` (class name string) and `record_id`.
